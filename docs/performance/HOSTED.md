# Hosted implementation and measurements

Baseline is commit 92a8e16. `node scripts/performance/benchmark-hosted-navigation.mjs results/performance/hosted-before.json` uses isolated SQLite data, 3 warmups and 30 samples at 6, 89 and 500 workspaces. Each workspace has 12 documents, 32 materials (8 assignments), 3 conversations of 40 messages, three years/two semesters and favorites; a selected thread has draft attachments. These service measurements deliberately exclude browser paint and real disk index extraction (index reads are counted through a deterministic fixture).

Confirmed causes: every navigation serialized and rewrote the full account, dashboard state loaded the selected document plus an unrelated index when both assignment ID and sourceKey were absent, and classified/projected hidden reader materials and messages. At 89 workspaces baseline dashboard-return p50/p95 = 13.8/17.3 ms; at 500 = 146.6/164.0 ms. Every 33-sample return sequence did 33 library writes, 66 index requests and 33 material projections. Raw samples include CPU, memory and response bytes.

Focused fixes: explicit session-only allowlist (unclassified new actions stay durable), absent-ID assignment guard, and dashboard projection avoids index loads, classification, material projection, conversation messages/source excerpts while retaining the destination, page, complete draft, image, files and owner. Behavioral work-count tests exercise this directly. Existing hosted document serving already uses file streams and bounded extraction workers.

Atomic `openReading` validates workspace ownership, available file, page and conversation policy before changing any navigation. It rechecks deletion/replacement after asynchronous availability checks, preserves the prior conversation draft, updates reading progress once and rejects superseded per-tab navigation generations. Legacy document/resume/source entry points call the same helper.

Revision transport v1 is opt-in; old clients retain full snapshots. `packages/core/src/state-surfaces.js` defines field ownership. GET `/api/state?surfaces=1` uses `X-Scholia-Revisions: {epoch,revisions}` and action requests opt in through `X-Scholia-State-Protocol: 1`. Missing/malformed/unknown bases and process/account epochs yield authoritative snapshots. A delta identifies its exact base. Cache validators include authenticated account, session, navigation, surface counters and the due-date clock. The server checks them before projection/serialization. Each cache retains only four served revision bases; snapshots are bounded to 256 sessions and 32 MB. Cached values are detached from mutable account data.

Authenticated `/api/events` streams only invalidation hints (`ready`, `change`, `heartbeat`), never a competing state store. It coalesces changes over 40 ms, bounds listeners (four/session, 256 total), closes slow/expired clients and shuts down cleanly. Conditional polling remains authoritative and reconnect starts with a full snapshot. Tests verify unchanged polls perform zero projection/encoding, session navigation omits catalog patches, malformed bases recover, account caches cannot cross, and event authentication/teardown works. Hosted focused/atomic/revision regression set: 39 passing tests.
